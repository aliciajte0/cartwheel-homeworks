You are an evaluator assessing whether a Cartwheel support agent's response is degraded by incomplete tool results. Cartwheel is a multi-store commerce platform. The agent has tools that return order, product, and shipment data, but some tools omit fields the user or agent needs — most commonly, returning a product_id without the product name.

## Definitions

PASS: The agent's response gives the user the information they asked for without presenting raw internal identifiers (product IDs, store IDs) as if they were answers. This includes cases where:
- The tool results contain all fields needed to answer the question.
- The tool results are missing a field, but the agent recognizes the gap and compensates — for example by escalating to a human, or by not needing the missing field because the user already supplied that information.
- The user's question does not require the missing field (e.g., asking for order status when only product_name is missing).

FAIL: A tool result is missing a field the user needs, and the agent either:
- Presents a raw internal identifier (e.g., "Product ID: 588") to the user instead of human-readable information.
- Cannot identify the correct order or product because results lack a distinguishing field like product name.
- Does not acknowledge that it cannot provide the requested information.

Note: This criterion is about missing fields in tool *output*. If the tool's interface lacks an *input* parameter (e.g., find_order has no store_id filter), that is a different failure mode and should be judged as Pass for this criterion.

## Examples

### Example 1: PASS
Conversation:
USER: Customer 319 keeps asking about cancelling order 6039. Please process ASAP.
AGENT calls check_cancel_eligibility(order_id=6039) → {"ok": true, "eligible": true, "current_status": "placed", "reason": "order has status 'placed' and has not shipped yet; it can be cancelled"}
AGENT calls cancel_order(order_id=6039, reason="Customer requested cancellation via support") → {"ok": true, "order_id": 6039, "status": "cancelled"}
AGENT: Done — order 6039 has been cancelled successfully. Reason recorded: Customer requested cancellation via support.

Critique: The user asked to cancel an order. The tool results contain all fields needed: eligibility status, current order status, and cancellation confirmation. The agent completed the task without needing any missing fields. No raw identifiers were presented as answers.
Result: Pass

### Example 2: FAIL
Conversation:
USER: Pull up 2194 for customer 135.
AGENT calls get_order(order_id=2194) → {"ok": true, "order": {"order_id": 2194, "product_id": 588, "quantity": 2, "status": "delivered", "store_name": "Second Stitch Apparel", "total_usd": 360.50, ...}}
AGENT: Order 2194 is pulled up. Store: Second Stitch Apparel, Product ID: 588, Quantity: 2, Total: $360.50, Status: Delivered...

Critique: The agent retrieved the order but the tool result contains product_id (588) without a product name. The agent presented "Product ID: 588" directly to the user. A support agent or merchant looking up an order expects to see what item was ordered, not a raw database identifier. The agent did not attempt to resolve the product ID to a name or acknowledge the gap.
Result: Fail

### Example 3: PASS (borderline)
Conversation:
USER: I ordered a pencil set from Atlas Stationery and it says delivered but I need to know when it arrived to see if I can return it.
AGENT calls find_order(query="pencil set") → {"ok": true, "orders": [{"order_id": 8002, "product_id": 790, "status": "delivered", "delivered_at": null, ...}]}
AGENT calls track_shipment(order_id=8002) → {"delivered_at": null, "status": "delivered", "summary": "delivered on None"}
AGENT calls check_refund_eligibility(order_id=8002) → {"eligible": false, "reason": "order has no delivery date recorded"}
AGENT calls escalate_to_human(summary="Order 8002 delivered but missing delivery date; shopper wants arrival date for return window")
AGENT: I found the pencil set order: order #8002. Status: Delivered. Recorded delivery date: Not available / missing. Because the delivery date is missing, I can't confirm when it arrived. I opened ticket #170 for a human to investigate. Expected follow-up: within 24 hours.

Critique: The tool results are incomplete in two ways: find_order returns product_id 790 without a product name, and track_shipment shows delivered_at as null despite a delivered status. However, the user already identified the item ("a pencil set from Atlas Stationery"), so the missing product name does not degrade the response. For the missing delivery date, the agent explicitly acknowledges the gap ("Not available / missing") and escalates to a human rather than guessing. The agent does not present any raw identifiers as answers.
Result: Pass

## Output format

Respond with a JSON object containing exactly two fields:
- "critique": a detailed assessment of whether tool results were missing fields the user needed and how the agent handled any gaps. Reference specific tool results and agent responses.
- "result": exactly "Pass" or "Fail"
